# api-decouper 第一版设计

状态：待用户审阅。本文记录已确认方向并补齐实现所需规则，不代表代码已实现。

## 目标与边界

作为宿主应用内的 Java / Spring 组件，将本地业务事务与外部 API 调用解耦。业务表和任务表必须使用同一个数据源、同一个事务管理器。

已确认：业务数据和任务原子提交；确定结果的本地应用和任务完成原子提交；业务实现 execute、recover、applyResult；通过 infeed-spi 适配业务实现；MQ 与扫描统一执行入口；使用数据库 CAS，不使用分布式锁。

第一版建议基线：延续 Java 8、Spring Boot 2.7，生产存储先支持 MySQL；测试使用真实 MySQL 语义验证并发。MQ 采用宿主提供的适配接口，不绑定某一产品。保留单 Maven 模块，按包隔离职责，暂不建设管理后台、跨库事务或通用流程编排。

成功标准：任务不会因 MQ 故障丢失；重复触发不能绕过抢占和到期检查；不确定的外部结果不会自动重发；结果应用失败不会重新调用外部 API；重启后能恢复路由和执行阶段。

## 接入契约

- submit：必须在宿主已开启的真实本地事务内调用，使用 MANDATORY 语义；返回真实 taskId。事务不存在时明确拒绝。
- execute：事务外调用外部系统，返回确定成功、确定失败、允许安全重试、结果未知之一。
- recover：处理结果未知和执行租约过期，返回确定结果、继续等待、安全重试或人工处理。默认人工处理，不默认重发。
- applyResult：同步、当前线程、组件事务内应用确定结果；只允许同库业务变更。异常必须向上传播，禁止异步、REQUIRES_NEW 或自行吞掉失败。
- 稳定的 operationKey 传给业务作为外部幂等键；所有尝试沿用同一键。外部系统是否支持此键由业务保证。
- 业务状态更新必须具有幂等和前置状态检查，禁止把“发起受理成功”直接解释为“支付完成”。

输入和结果使用带版本的 JSON 文档及显式编解码接口，不依赖 Java 类名反序列化。金额示例使用 BigDecimal。异常摘要与结果应限长和脱敏，不保存密钥或原始敏感响应。

## SPI 路由

任务持久化 bizType、handlerVersion。适配器将二者解析为唯一的 infeed-spi 实现名称；路由一经提交不可随默认配置漂移。

核心执行器仅依赖 HandlerResolver，不直接依赖 SPI 代理。infeed-spi 适配器必须在发生业务副作用前确定唯一目标；不得用多实现广播后检查结果数量的方式保证唯一性。缺失实现、多重匹配、版本不支持均进入人工处理并告警，不视为空结果成功。

infeed-spi 只负责发现和选择，三个业务方法必须针对同一已解析目标同步调用。不得使用其并发分发执行 applyResult，commit/rollback 接口不作为外部 API 的事务保证。实现时核对已发布 1.0.0.RELEASE 的容器、代理及 Spring 事务代理兼容性；若只能获得多播执行能力，适配器应直接基于其注册容器解析唯一 Spring 目标，禁止静默回退到广播。

旧版本任务需要保留对应实现；删除实现前确认无存量任务。启动验证静态路由冲突；执行时验证当前任务路由。

## 状态机

| 状态 | 动作及后继 |
| --- | --- |
| READY | 到期后 CAS 进入 EXECUTING，调用 execute |
| EXECUTING | 确定结果进入 RESULT_READY；安全重试进入 RETRY_WAIT；未知进入 UNKNOWN |
| RETRY_WAIT | 到期后 CAS 进入 EXECUTING；复用原 operationKey |
| UNKNOWN | 到期后 CAS 进入 RECOVERING，只调用 recover |
| RECOVERING | 确定结果进入 RESULT_READY；等待回 UNKNOWN；业务批准重试进入 RETRY_WAIT；否则 MANUAL |
| RESULT_READY | 到期后 CAS 进入 APPLYING，只调用 applyResult |
| APPLYING | 业务更新和 DONE 同事务提交；失败回 RESULT_READY 并安排退避 |
| DONE | 终态；重复触发直接跳过 |
| MANUAL | 自动执行停止，保留证据及告警 |

EXECUTING、RECOVERING 租约过期通过 CAS 转 UNKNOWN；APPLYING 租约过期通过 CAS 返回 RESULT_READY。结果已持久化的任务不得回到外部执行阶段。

execute 或 recover 未分类异常默认 UNKNOWN。解析错误、路由错误等确定的本地配置错误进入 MANUAL。明确业务失败也是确定结果，applyResult 成功后进入 DONE，任务完成不代表业务成功。

## 事务与崩溃窗口

1. 业务事务内插入业务数据及 READY 任务，注册提交后 MQ 通知；回滚不发消息。提交后发送失败不改变已提交结果，由扫描兜底。
2. 短事务 CAS 抢占并提交，之后事务外执行 API。不得持有数据库事务等待网络调用。
3. 用执行令牌条件更新，持久化确定结果与 RESULT_READY，再进入结果应用阶段。写库失败则保留当前执行状态，由租约恢复进入 UNKNOWN，禁止直接重发。
4. 短事务 CAS 抢占 RESULT_READY 为 APPLYING。
5. 新短事务先以任务行锁核验状态、令牌并锁定任务行，再同步 applyResult，最后条件更新 DONE；任何所有权校验失败均回滚业务变更。
6. applyResult 失败导致上述事务整体回滚；事务外按原令牌安排结果应用退避。若进程退出，APPLYING 租约恢复只补结果应用。

步骤 5 持有任务行锁，避免结果应用途中租约被另一节点收回。回收器必须等待并重新判断 CAS，不能凭之前扫描的快照无条件更新。applyResult 必须是有事务超时的短本地数据库操作。

外部成功但本地结果尚未保存即崩溃，无法由组件独立判断外部事实，必须交 recover 核实。CAS 只保护本地所有权，不能撤销仍在执行的外部请求，也不承诺外部恰好执行一次。

## 数据模型与索引

主表 local_task：id、biz_type、handler_version、biz_id、operation_key、payload、payload_version、status、result_payload、result_version、result_outcome、execution_token、lease_until、version、execute_attempts、recover_attempts、apply_attempts、next_execute_time、last_error_code、last_error_summary、create_time、update_time、completed_time。

约束：operation_key 全局唯一，业务需使用带业务命名空间的稳定值；同键同输入提交返回已有任务，同键不同路由或输入拒绝。插入并发冲突通过唯一约束处理，禁止先查后插作为唯一保障。业务层必须同时保证自身订单创建幂等。

索引：(status, next_execute_time, id)、(status, lease_until, id)、(biz_type, biz_id)。状态使用明确枚举编码；时间基于数据库 UTC，避免节点时间差导致错误回收。结果、输入长度设上限。

任务事件表 local_task_event 记录状态变更、尝试类型、令牌、结果分类、错误摘要和时间；状态变更与事件在同事务写入。不会把外部调用日志宣称为原子审计。已完成任务按保留策略归档；第一版不自动删除幂等键，避免旧任务被重复提交。

## CAS 与执行容量

所有入口统一读取持久化状态。抢占条件同时包含 id、version、允许状态和到期时间，成功后生成新 executionToken、增加版本及对应阶段次数。完成、错误回写和续租均检查状态和令牌，更新零行表示失去所有权，必须停止推进。

租约支持续期，但续期不证明外部操作安全。调用超时、租约时长、线程容量可配置；安全恢复仍依赖业务核实。先取得有界执行容量再抢占，拒绝入队不把任务遗留为已抢占。

扫描默认每五秒触发，各实例可并行扫描并 CAS 抢占。按各状态分别分页，使用 next_execute_time/id 稳定游标和单轮时间、条数预算；扫描与执行线程隔离，避免慢 API 阻塞扫描和恢复。第一版不要求集中式调度器或分片基础设施。

MQ 仅传 taskId。DONE、未到期、竞争失败可确认消息；数据库读取失败由适配器报告可重投。调度始终保留恢复能力，MQ 确认不是任务完成标记。

## 重试与人工恢复

外部重试仅由业务明确授权，业务提供原因及下次时间；组件限制最大尝试次数和任务期限，超出预算转 MANUAL，不把 UNKNOWN 转确定失败。recover 与 applyResult 使用各自次数和退避，不混用 execute_attempts。

结果应用采用可配置指数退避和抖动，达到预算转 MANUAL，保留确定结果。人工恢复第一版提供受宿主鉴权控制的服务接口，不暴露默认公开 HTTP 端点；要求操作原因、期望版本并记录事件，继续遵守原阶段和未知结果规则，禁止提供无校验强制重发接口。

外部异步通知仍由业务处理订单状态；applyResult 要通过业务状态机防止旧受理结果覆盖已到达的终态。第一版不提供通用外部通知入口。

## 装配与告警

自动配置提供 JDBC 仓储、事务执行器、SPI 适配器、扫描器及有界线程池；数据源和事务管理器显式绑定，多数据源歧义时启动失败。示例移动到测试或示例目录，禁止自动注册到宿主。不自动执行生产 DDL，提供版本化建表脚本。

MQ 发送器可选，无发送器时仅扫描。告警提供事件和接收器接口，默认结构化日志；接收器异常不改变任务业务状态。指标标签限制为业务类型、阶段、结果，taskId 仅进入日志和事件。

规则包括：积压数量、最老待执行时长、租约过期、UNKNOWN 停留、结果应用失败、恢复预算耗尽、路由或编解码异常、MQ 持续失败、扫描无进展。阈值、持续窗口、聚合、冷却和恢复通知可配置。正常 CAS 竞争仅统计指标。告警是可重建的状态监测，不承诺外部告警通道恰好投递一次。

## 验证与交付

单元验证：状态转移、未知结果默认策略、阶段预算、路由唯一性和编解码。

数据库集成验证：业务和任务共同回滚；真实 ID 与幂等键冲突；MQ/扫描并发只成功抢占一次；到期检查；旧令牌不能写回；外部调用后崩溃进入 recover；结果应用失败不重调 API；业务更新和 DONE 原子回滚；租约回收与本地结果事务竞争；MQ 不可用时扫描完成任务。

交付包括建表脚本、自动配置、支付示例、接入文档和上述验证。修复或替换当前占位仓储与执行器，保留不相关工具代码。发布、升级依赖和多产品 MQ 适配不在本轮隐含授权范围内。
