# 实现取舍与审查记录

## 已落实的技术选择

1. 在用户指定的 feature/reliable-local-tasks 分支、当前检出目录实现，没有额外创建 worktree；原始 main 保留。
2. 数据库集成测试采用 Docker CLI 临时 MySQL，替代计划中的 Testcontainers，减少测试运行依赖；代价是执行测试需要 Docker。脚本仅清理自己创建的实例。
3. SLF4J API 对齐 Spring Boot 2.7 的 1.7.36，修正原框架 API 2.x 与日志后端的版本冲突。
4. 原型契约、仓储及执行器互相依赖，合为一个经过验证的核心提交，避免引入临时兼容接口。后续装配、告警、示例及审查修复单独提交。
5. 时间存储为数据库生成的 UTC epoch 毫秒 BIGINT，避免 JDBC/JVM 时区转换歧义；宿主读取数据时需要按毫秒解释。
6. 最大任务年龄只限制新外部执行；核实及本地结果应用采用各自尝试预算，以便核实已产生的外部效果。人工恢复不开启新的外部执行预算。
7. 审计事件与任务更新放在同一仓储事务中，未另设 TaskEventRepository，防止事务边界被拆散。
8. 原代码 Javadoc 包含自定义 @date 标签导致 verify 失败，通过插件配置支持该标签和关闭旧代码 doclint，未改动无关工具代码。
9. 支付示例的 Jackson 为测试依赖，统一到 BOM 2.17.3，修复实际出现的 core/databind 版本不匹配；组件本身仍由业务提供编解码实现。
10. 告警在实例内聚合，跨实例去重由宿主告警平台承担；否则多个实例可能重复通知，组件不为告警引入分布式锁。
11. 增加 LONG_RUNNING 规则检测持续续租的卡住任务，仅告警，不自动重发。外部调用的网络超时由宿主网关配置，组件无法安全撤销未知的外部副作用。
12. 按用户要求保留分支及原始基线，不合并、不推送、不发布。

## 独立审查和修复

独立审查发现三项 P2 问题，均已通过回归测试验证修复：

- 监控数据库查询失败时，完整快照语义误发其他规则的恢复通知。增加局部观测模式，只变更确实观测到的规则。
- 过期 APPLYING 行锁阻塞扫描线程，导致其他 READY 任务错过扫描预算。回收移入独立有界线程池，去重并计入扫描预算；测试同时持有过期结果应用行锁和无关 READY 任务。
- 长期卡住的外部调用持续续租，不会触发租约过期告警。增加独立于租约有效性的阶段时长告警。

自查额外复现并修复：提交冲突被业务捕获后，原来仅检查活动事务，未将其标记为 rollback-only。现通过真正的 MANDATORY 事务模板包裹提交；外层捕获异常仍无法提交这次业务变更。

审查未留下待修复的重要问题或延期的小问题。验证范围和生产接入边界见 acceptance.md。

最终验证：2026-10-14（Asia/Shanghai），`mvn clean test` 13/13 通过；`bash scripts/mysql-test.sh` 13 个单元测试 + 31 个真实 MySQL 集成测试通过，0 跳过。JAR 已检查包含自动配置及 DDL、不包含支付示例。


## 后续结构调整（以此节为当前约定）

按用户要求调整为父 POM + api-decouper-starter + api-decouper-starter-samples 多模块，samples 的公共支持、支付、可靠性分成三个子模块。先前记录中的“单模块”和“临时 Docker 实例”仅描述历史验证方式。

当前不再自动管理数据库容器；只使用用户提供的现有专用测试库及受限账号。凭据仅通过临时环境变量注入，不进入仓库；运行数据库案例前显式允许重建专用库内的测试表。


模块化审查补强：Central 发布插件使用显式 excludeArtifacts 排除 samples 父模块与全部案例，不只依赖 Maven deploy.skip。新案例注册时同步更新排除列表。公共测试基座以同机进程锁串行保护共享测试库，避免 -T 并行的案例互相 DROP 表；这不改变组件的 CAS 机制或依赖方向。

发布排除配置参照 [Sonatype 官方配置说明](https://central.sonatype.org/publish/publish-portal-maven/#excludeartifacts)，保持原插件版本。本轮仅验证构建及配置，没有执行部署或上传。
